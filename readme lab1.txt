Grocery Delivery App

I have developed the user story map for Grocery Delivery App by brainstorming ideas of what a delivery app should have for the best user experience. I have focused on adding more features for the application from my customer’s POV.
The main customer journey starts with discovering groceries, continues through building a cart and checking out, and ends with receiving and tracking the delivery. Account and order management features were also included because they provide useful functionality for returning customers.
Here are a few decisions I made:
1. Include four epics: Discover Groceries, Build & Place Order, Delivery, and Account & Order Management.
I made this decision because these four areas represent the major functional parts of a grocery delivery app. Organizing the map this way makes it easier to understand the app from the customer's perspective. This decision is captured in the user story map by using these four areas as the main backbone sections.
2. Prioritize the basic grocery ordering process for the first release: I decided that customers should first be able to browse products, search for products, add products to a cart, enter a delivery address, select a delivery time, create account, pay for an order etc. These features are necessary for the application to provide its main purpose.
3. Move delivery and account-management features into a second release:
Since features like delivery tracking, notifications, order history, and reordering are useful, but they are not all required for the most basic version of the application, I chose to put them in release 2.
4. Leave some features unscheduled: I decided not to assign every story to a release because some features are lower priority and could be developed later. For example, saving favourite products and reordering previous groceries can be considered future upgrades.
5. Colour code stories and ideas to differentiate: I have used various colours to differentiate the cards and make the story map clearer and more understandable to anyone looking at it the first time.
Extra features that I have added to my story map:
In this project work, I had started with a limited amount of knowledge, but I explored various features on StoriesOnBoard to make my story map more attractive, organized and detail oriented. I have changed colours of the cards, added multiple personas and used annotations (idea, thought, doubt etc.). Moreover, I have also used the timeline feature to give both the releases a timeline for completion and gave status (to do, doing, ready etc.) to a few stories. This was not required for the basic user story map, but it made the map easier to read and understand.
